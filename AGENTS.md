## Architecture rules

- Client data access goes through the feature modules `src/features/<entity>/{api,hooks,types}.ts` (tasks, notes, projects, milestones, automations, dependencies, search; shared query keys `qk`, `useCrud` cache helpers, session/date/preload helpers in `src/features/shared`), re-exported by the compatibility barrel `src/lib/data.ts` (TanStack Query keys `tasks/projects/notes/milestones`); features must not import each other in cycles (shared code goes in `src/features/shared` or `src/lib`); why: one cache keeps list, kanban, calendar and timeline in sync with optimistic updates.
- Task create/edit happens only via the global `TaskDialogProvider` (mounted in `_authenticated` layout); why: every view opens the same full editor.
- Team access is enforced in RLS via security-definer `is_project_member`/`is_project_owner`; tasks/notes/milestones in a shared project are visible to members; why: avoids recursive policies and keeps sharing project-scoped.
- Two-factor (TOTP, Supabase MFA) is enforced in three places: the `_authenticated` guard (`requireSession` sends `aal1` sessions of users with a verified factor to the TOTP step on `/login`), `requireSupabaseAuth` (refuses their `aal1` tokens via `mfa_satisfied()`), and a `RESTRICTIVE` RLS policy `mfa_aal2` on every RLS table (migration 0022) that new tables must also get; why: the anon key is public, so only the database can stop an `aal1` token from reading data.
- Public read-only links (`/s/$token`, migration 0024) are the only anonymous data path: `public_shares` stores only `sha256(token)`, `can_share_resource()` decides who may publish (note creator or project owner; project owner), and the page reads through `getPublicShare` → `src/server/publicShare.server.ts`, which uses the service role scoped to one share and one resource and returns a field-by-field DTO (no ids/emails, `[[links]]` as text, refs only from other public notes of the same owner, every failure a 404); why: a bearer link must never widen what RLS protects or reveal whether a token exists.
- Drag & drop uses `@dnd-kit/core` (kanban, calendar); timeline bars use raw pointer events; why: dnd-kit lacks resize semantics for gantt bars.
- Task dependencies live in `task_dependencies`; blocked checks, cycle rejection and auto-shift of dependents run in `useTaskActions` (src/features/tasks/hooks.ts) and `useDependencyActions` (src/features/dependencies/hooks.ts); why: every view (list, kanban, calendar, timeline) shares one mutation path. Auto-shift and completion (blocked check + next recurring occurrence) are the Postgres RPCs `shift_task_dependents` / `complete_task` (migration 0017), also called by the n8n service, so change the rules there, not in TypeScript.
- Automations are evaluated server-side in `runAutomations` (src/lib/automations.functions.ts), triggered from `useTaskActions` (task rules, `runAutomationRules`) and `useNoteActions` (note rules, `runNoteAutomationRules`) after create/update, and by server-side writers (n8n task writes, `createNote`); actions write directly so they never re-trigger rules, and note triggers are matched against the note as the user's write left it; why: avoids loops and keeps webhooks/Telegram secrets on the server.
- Scheduled automations (`trigger.type = "schedule"`, `schedule_cron`/`schedule_tz`, migration 0023) are validated by the local cron parser `src/lib/cron.ts` (shared by the form preview and `scheduleAutomation`, which stores `next_run_at`) and run by n8n workflow 10 via `POST /api/public/n8n/automations/tick` (`runDueAutomations`), which claims each window with a compare-and-swap on `next_run_at`; their actions are limited to create_task, move_overdue (never to done) and digest; why: Vercel Hobby cannot schedule, and the CAS makes overlapping ticks and retries run a window once.
- Notes store `blocks` (jsonb, block ids) as source of truth and mirror markdown into `content` for search/AI, plus derived `links`/`refs`/`excerpt` columns (migration 0018, `withNoteIndex`/`noteIndexFields`) that every note writer fills so backlinks are a GIN-indexed `note_backlinks` RPC and the list only loads the excerpt; links `[[title]]`, refs `((blockId))` and queries are parsed client-side in src/lib/blocks.ts; why: backlinks/graph/transclusion need stable block ids without extra tables.
- Natural-language task parsing is a local regex parser (src/lib/nlp.ts); why: instant preview with no AI cost.
- Message-to-task capture (Telegram app/n8n mode, n8n capture, inbox "Jadikan tugas (AI)") runs server-side in `src/server/taskCapture.server.ts`: AI structured extraction (`aiExtractTask`, candidate names only) gated by `assertAiAvailable` + the per-user AI budget, regex fallback (`fallbackExtraction` → nlp.ts), every reference validated by `resolveExtraction` (src/server/taskExtract.server.ts) and dependencies cycle-checked with `createsDependencyCycle` (src/lib/task-rules.ts); Quick task (Q) stays regex-only; why: one pipeline fills every field without ever trusting model-supplied ids.
- Message-to-note capture (Telegram `/note` and note-like text, n8n capture `target=note|auto`, inbox "Jadikan catatan (AI)") runs in `src/server/noteCapture.server.ts` with the same AI-or-fallback gate (`extractWithFallback`): `aiExtractNote` (names of projects, notes and tags only) → `resolveNoteExtraction` (src/server/noteExtract.server.ts: typed blocks, project/tag/`[[link]]` matching, invented links and refs stripped) → insert via `withNoteIndex` → `runNoteAutomationRules`; the in-app "Catatan dari teks" form (notes list, project page, graph) calls `draftNoteFromText` and only prefills, the user reviews and saves through `useNoteActions`; the project and template dialogs get the same draft-only "Isi dari teks" (`src/lib/prefill.functions.ts` → `src/server/formPrefill.server.ts`), with member names only as suggestions from existing contacts (never auto-invited); why: notes get the same validated, never-trust-the-model pipeline as tasks, and in-app AI never saves or invites behind the user's back.
- Semantic search embeddings live in `semantic_documents` (migration 0020, one row per task/note, `model` + `content_hash`) and are filled by an incremental queue (`semantic_pending` → `aiEmbed` → `semantic_upsert`, src/server/semantic.server.ts) triggered after saves by `scheduleSemanticSync` (debounced, from `useCrud`), before searches, by Settings "Indeks ulang" and by n8n maintenance; why: saves never wait on an AI provider and edits made anywhere (n8n, other devices) are picked up by content hash.
- All authenticated pages use the shared `PageContainer`; why: horizontal spacing and responsive widths remain consistent across views.
- Per-user Google Calendar access uses the app's own Google OAuth 2.0 client (code + PKCE, encrypted user-bound `state`) and stores only AES-GCM-encrypted refresh tokens (`TOKEN_ENCRYPTION_KEY`) in service-role-only `app_user_connections`, refreshed server-side; why: provider credentials must never reach the browser, n8n or other users.
- n8n integration endpoints live in `src/routes/api/public/n8n/*` behind `handleN8n` (`x-api-key` = `N8N_API_KEY`, zod validation, idempotency via `n8n_events`); they use the service role only inside handlers, scope every query to the resolved user and reuse the server-side task rules; schedules (reminders, digests, maintenance, backups) run in n8n; why: Vercel Hobby/Supabase Free cannot schedule, while domain logic must stay in one place.
- Note collaboration uses Yjs updates over authenticated realtime channels, while durable note state remains in `notes.blocks`; why: concurrent edits converge without introducing a second source of truth.
- Deleting tasks/notes/projects is a soft delete (`deleted_at`), archiving sets `archived_at`; list queries in `src/features/*/api.ts` exclude both and `/archive` restores or purges; why: users can recover mistakes without a second copy of data.
- Reports aggregate in Postgres (`report_daily`, migration 0026, `SECURITY INVOKER`, days cut in the browser's time zone) behind `src/features/reports`, and charts are the dependency-free components in `src/components/charts` (theme tokens `chart-1`/`chart-2`, legend for 2+ series, keyboard readout, table twin); habits (`habits`/`habit_logs`, migration 0025) are owner-only, soft-deleted/archived like tasks, with streak/rate math in `src/lib/habits.ts`; why: charts never download the task history, stay accessible in both themes, and add no chart dependency.
- Long lists paginate client-side via `usePaged`/`LoadMore` (src/components/common/LoadMore.tsx); why: one consistent "load more" pattern without changing the shared query cache.
